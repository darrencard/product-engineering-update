# Slide 9b: Delivery on a page

Act: Delivery. Audiences: Board.

## The question it answers

For a board, did we deliver, at what cost to quality, and are we safe?

## Required data

Nothing new. It condenses four leadership slides.

| Source | What the slide reads | Required |
|---|---|---|
| Issue tracker | Last period's commitments, each with one target metric named before launch | Yes |
| Product analytics | The result for each target metric | Yes |
| Source control and CI | Deploys, lead time, review time and change failures | Yes |
| Incidents and status | Time to restore | Yes |
| Developer survey | The developer experience index | No |
| Incidents and status | Availability objectives, error budgets and incident data | Yes |
| Security tracker | Audit status and vulnerability ageing | Yes |
| Documents | The architecture decision log and debt register | No |
| AI tool admin data | Usage and cost per engineer by tool | Yes |
| Source control and CI | A baseline from before the tools, and the quality metrics from slide 9 | Yes |
| Developer survey | Developer sentiment | No |

## Minimum evidence to render

At least one of these blocks, filled from computed data: `cards`.
If the data is missing, put a `data_needed` block in its place with an owner and a due date. Never fill the gap with prose.

## The rule

Board cut only. Keep security and AI governance on this page every quarter, even when nothing changed.

## Time window

State the window on the slide's `asof` line. In the example: "Condensed from slides 8, 9, 10 and 13 of the leadership cut. Q3 FY26."

## Titles

- Good: "We shipped 9 of 11 commitments and faster than last quarter. Review time is the cost." (a claim someone can check).
- Bad: "Delivery on a page" (a label; it claims nothing).
